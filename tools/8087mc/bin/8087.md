# Intel 8087 microcode explained

Each x87 instruction has an opcode of 11 bits. I'll call it a macro-opcode to distinguish it from the microcode opcodes.

The microcode consists of 16-bit words, and there are 1648 words in total. There are two temporary registers called tmpA and tmpB, they can hold a full 80-bit floating point value each.

I will denote individual bits with letters: `ABCDEFGHIJKLMNOP` with A being the most significant bit, and P the least significant bit.

# Opcodes

## Data movement

`ABC=000` Copies data from one register to another. Data: `DEFGH` (source register) and `KLMNO` (target register).

The `P` bit provides assorted adjustments to some operations. `I` and `J` are sometimes also used.

List of known register indices:

0x00: shift count (source only)

0x01: exp convert logic (source only)

0x02: st(0) w/tag

0x03: st(i) w/tag

0x04: bus interface unit

0x05: exp constant (source only). Index specified (previously or concurrently) by FGHI with `ABC JO = 000 10`. Constant also affected by opcode.

0x06: zero - this one is also used as a target and I don't know what it means there.

0x08: exponentA

0x09: signA, exponentA

0x0a: fractionA

0x0b: tmpA (sign, exponent, fraction, tag)

0x0c: exponentB

0x0d: signB, exponentB

0x0e: fractionB

0x0f: tmpB (sign, exponent, fraction, tag)

0x10: sumreg

0x11: sumreg and 3 rounding bits

0x12: sumReg and sign

0x13: sumReg and sign and 3 rounding bits

0x14: shift left out X

0x15: source: shift right out

0x15: destination: loop counter. `J=0` loads from fraction bus (typically constant ROM). `J=1` loads from microcode DEFGHI.

0x16: quotient register

0x17: tmpC

0x18 (source): trig CORDIC constant selected by loop counter

0x19 (source): log CORDIC constant selected by loop counter

0x1a (source): misc constant selected from the instruction opcode (a few also use a flag).

0x1b: bottom bit set (source only)

0x1c: shift left out Y, difference between X&Y unknown

0x1d: (not used)

0x1e: Reads bottom two bits from state machine (source only). For multiplication?

0x1f: top two bits of fraction set to 1 for NaN (source only).

As a modification to any source, the top bit is set by `ACJP = 0001`

## Control flow

`ABC=100` Far jump. The target is in `DEFGHI`, an index to a lookup table. Read more in "Jump targets".

`ABC=101` Far call.  The target is in `DEFGHI`, an index to a lookup table. Read more in "Jump targets".

`ABC=110` Local jump. The offset is a *signed* value in `DEFGHI`, and is added to the address of the next instruction. So, backward jumps have the `D` bit set for a negative value.

`ABCDEFGHI=111000000` Return from subroutine call.

All jumps, calls and returns use `JLKMNO` as the condition for the jump. The `P` bit inverts the condition. For example, `JKLMN..` is an unconditional jump/call. Curiously, `JKLMN.P` is used exactly once - it's the inverse of an unconditional jump/call, meaning "never take this jump/call"?

`ABCDEFGHIJKLMNO.` Everything 1 except P=0. Read next instruction - return from processing the current instruction.

`ABCDEFG.IJKLMNO.` Everything 1 except HP=0. Read next instruction, but only in the `#0675` and `#0695` functions.

## Bitshifts

`ABCJ=0010` performs a bitshift. `DEFGH` is the input register. 

`I=1` is a right shift `>>` and outputs to register `0x15`. 

`I=0` is a left shift `<<` and outputs to registers `0x14` and `0x1c`, the difference between them is not clear yet. 

Shift amount is in `KLMNOP`. 

If `J=1`, it's unclear if it does a shift. Maybe it loads a constant using `DEFGHI` as an index, then does the shift as usual.

## "B operation" (unknown)

`ABC=010` performs something. Seems to output to register 0x10 when `L=0`, or 0x11 when `L=1`. Seems to use `DEFGH` as an input register and `MNO` as a parameter or maybe operation code. Function of `IJK` or `P` totally unknown. More parameters?

- `ABC IJ = 010 11`: controls skip shifter and rounding in complex ways
- `ABC IJ = 010 01`: different rounding

## "BC operation"

- `ABC DEFG IJ = 011 0100 00`: controls rounding bits
- `ABC DE IJ = 011 01 01`: bits FGH to rounding bits
- `ABC DEFGH IJ = 011 01010 00` or `A DEFGH = 0 100?1` (x11 or x13): sum register to rounding bits
- `ABC DEF I = 011 111 0`, controls a state machine for the bottom two bits, using the value of `O`. Maybe for multiplication? Value is read into the bottom two bits by `A DEFGH = 0 11110` x1e.
- `DE I MNO = 01 0 001`: cond28 to condition bit C1
- `DE I MNO = 01 0 011`: bit 0 to condition bit C1, bit 1 to C3, bit 2 to C0
- `DE I MNO = 00 1 111`: exp bit 15 to condition bit C2
- `DE I MNO = 00 0 100`: update st tag
- `DE I MNO = 00 0 100`: condition to st tag
- `DE I MN = 00 0 01`: update tmpA tag
- `DE I MN = 00 0 11`: update tmpB tag

## ABC instructions

All these instructions have `ABC=111`, `DEF` is the type and `MNO` is the parameter, other bits are always zero.

### Type 4: Exceptions

`ABCD........   .` Set exception.

- "DE denorm" set by `ABC DEF MNO=111 100 000`
- "IE invalid" set by `ABC DEF MNO=111 100 001`
- "PE precision" set by `ABC DEF MNO = 111 100 010`, updated by `ABJKLMNO = 11011101` maybe?
- "ZE division by zero" set by `ABC DEF MNO=111 100 011`
- "OE overflow" and "UE underflow" set/cleared based on the evaluated state: `ABC DEF O = 111 001 1`

### Type 4/5: Constant selection

- `ABC=111 DE=10 MNO=101`: clear or set constant selection based on F. Switches between ln(2)/3 and 3*log2(e) versus log2(e) and sqrt(2) for instructions F2XM1, FYL2X, FYL2XP1. This is a special case for these two pairs of constants. Unclear why this doesn't set an exception.

### Type 5:

Parameters 4, 5, 6, 7.

## Stack manipulation

`.BCDE...........` Increment stack pointer (pop).

`.BCDE.........O.` Decrement stack pointer (push).

## Miscellaneous
