# Intel 8087 microcode explained

Each x87 instruction has an opcode of 11 bits. I'll call it a macro-opcode to distinguish it from the microcode opcodes.

The microcode consists of 16-bit words, and there are 1648 words in total. There are two temporary registers called tmpA and tmpB, they can hold a full 80-bit floating point value each.

I will denote individual bits with letters: `ABCDEGHIJKLMNOP` with A being the most significant bit, and P the least significant bit. In mask definitions, an uppercase letter means the bit is set, and a dot `.` means the bit is unset.

# Opcodes

## Data movement

`...     ..     .` Copies data from one register to another. The opcode looks a bit silly but it's all zeros except for DEFGH (source register) and KLMNO (target register).

List of known register indices:

0x02: st(0)

0x03: st(i) - i probably comes from the macro-opcode.

0x06: zero - this one is also used as a target and I don't know what it means there.

0x0b: tmpA

0x0e: tmpB

## Control flow

`A..` Far jump. The target is in `DEFGHI`, an index to a lookup table. Read more in "Jump targets".

`A.C` Far call.  The target is in `DEFGHI`, an index to a lookup table. Read more in "Jump targets".

`AB.` Local jump. The offset is a *signed* value in `DEFGHI`, and is added to the address of the next instruction. So, backward jumps have the `D` bit set for a negative value.

`ABC......` Return from subroutine call.

All jumps, calls and returns use `JLKMNO` as the condition for the jump. The `P` bit inverts the condition. `JKLMN..` is an unconditional jump/call. Curiously, `JKLMN.P` is used exactly once - it's the inverse of an unconditional jump/call, meaning "never take this jump/call"?

`ABCDEFGHIJKLMNO.` Read next instruction - return from processing the current instruction.

`ABCDEFG.IJKLMNO.` Read next instruction, but only in the unreachable(?) `#0675` function.

### Jump conditions

0x00: is_memory_operand

0x01: (opcode&0x7C0) == 0x4C0

0x02: stack_empty

0x06: pop_at_end

0x0a: opcode&1

0x0b: double_pop_at_end

0x20: tmpA zero

0x22: tmpA bad?

0x23: stack overflow

0x24: tmpB zero

0x26: tmpB bad?

0x27: st(i) doesn't exist (A)?

0x2f: st(i) doesn't exist (B)?

0x38: accumulator!=0

0x3e: unconditional

## Exceptions

`ABCD........   .` Set exception. The bits `MNO` contain the exception index from 0 to 5 in the same order as in the status word, except the bit `O` is inverted. So: 

- 0="denorm"
- 1="invalid"
- 2="overflow"
- 3="division by zero"
- 4="precision"
- 5="underflow"

## Stack manipulation

`.BCDE...........` Increment stack pointer (pop).

`.BCDE.........O.` Decrement stack pointer (push).

There are two that are seemingly related, but I don't know what they do yet:

`.BCDEF..........` Increment something?

`.BCDEF........O.` Decrement something?

## Miscellaneous

`ABCDEFGHIJKLM...` No operation. NOP.

`...      JKLM...` Loads a constant from the ROM. Parameter in `DEFGHI`. Parameter might be the destination register - how do we decide which constant to read? Random logic not in the microcode?
